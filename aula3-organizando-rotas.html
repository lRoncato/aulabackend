ANTES DO CÓDIGO

O que é um "plugin"?

O app nasce no server.ts. Se a rota vai pra outro arquivo, como esse arquivo faz app.get(...)?
Resposta: o outro arquivo vira uma função que recebe o app.
▤ users.routes.ts · "me dá o app" export async function usersRoutes(app) {   app.get("/", ...) }
▤ server.ts · "toma o app" const app = fastify()   app.register(usersRoutes)
O REGISTER FAZ ISSOapp.register(usersRoutes) ≈ usersRoutes(app)
O Fastify chama a sua função e entrega o app pra ela.
Plugin = o nome que o Fastify dá pra "função que recebe o app".

OBJETIVO

Tirar o mistério da palavra "plugin": é só uma função comum que recebe o app como parâmetro. Nada de novo além de função com parâmetro.

CONDUZA ASSIM

  • Comece pela pergunta do step 1 e deixe a turma pensar: "o app está no server.ts, como o outro arquivo usa ele?". Alguém costuma sugerir "importar o app", e é aí que entra a ideia de receber por parâmetro.
  • Por que não importar o app direto do server.ts? Porque o server.ts importa as rotas: se as rotas importassem o server.ts, um arquivo dependeria do outro e vice-versa (import circular). Recebendo por parâmetro, o arquivo de rotas não precisa conhecer o server.ts.
  • Por que register e não chamar usersRoutes(app) direto? Porque o register também aceita opções, como o prefix do próximo slide, e o Fastify garante que as rotas estejam prontas antes de ligar o servidor.
  • Não entre em encapsulamento e hooks agora.

UMA ETIQUETA PRO TYPESCRIPT

O que é o FastifyInstance?

É o tipo do app. Serve só pro TypeScript saber o que o app é.
▤ server.ts · o TS descobre sozinho const app = fastify() // ele viu de onde o app veio
▤ users.routes.ts · sem o tipo function usersRoutes(app) { ... } // erro: 'app' tem tipo 'any'
Parâmetro de função chega sem o tipo. O TS não sabe que o app tem .get, .post...
▤ users.routes.ts · com o tipo import type { FastifyInstance } from "fastify" function usersRoutes(app: FastifyInstance) { ... } // "esse app é igual ao do server.ts" · autocomplete volta
Instance
instância: o objeto que o fastify() cria
import type
é só tipo: some quando o TS vira JS, não muda nada rodando

OBJETIVO

Explicar por que o arquivo de rotas precisa de um import que o server.ts não precisava.

CONDUZA ASSIM

  • Faça ao vivo: apague o : FastifyInstance e mostre o sublinhado vermelho no app. Digite "app." e mostre que o autocomplete não sugere nada. Coloque o tipo de volta e o autocomplete aparece.
  • Analogia: é uma etiqueta no parâmetro pra o VS Code saber o que tem dentro da caixa.
  • Não precisa entrar em interfaces/generics. Basta: tipo = descrição do formato do valor.

COMO A URL É MONTADA

prefix + rota = URL final

/users+/=
GET /users lista todos
/users+/=
POST /users cria um
/users+/:id=
GET /users/:id busca um (em breve)
CUIDADOEscrever app.get("/users") dentro do arquivo vira /users/users. O prefixo já foi colocado.

OBJETIVO

QUANDO DÁ ERRADO

Erros que vão aparecer

404
Esqueceu o app.register no server.ts, ou repetiu o caminho e criou /users/users.
módulo
Cannot find module: faltou o .js no import, ou o ../ pra sair da pasta routes.
export
does not provide an export named: esqueceu o export antes da função, ou o nome está diferente no import.
tipo
TypeScript reclamando de app: faltou o : FastifyInstance no parâmetro.

OBJETIVO

Antecipar os erros que mais aparecem nessa aula, pra turma reconhecer a mensagem quando ela surgir.

CONDUZA ASSIM

  • Por que o .js se o arquivo é .ts? O projeto usa "type": "module" e o TS resolve o .js para o .ts. É a regra dos imports em ESM.
